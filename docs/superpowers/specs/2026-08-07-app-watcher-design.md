# 子项目：前台应用监控与观众群体系 设计

日期：2026-08-07
状态：已批准（用户确认：播报走 AI 生成；观众群多样性；设置页 ？tooltip 帮助模式；vanilla 拆分）

## 目标

监控"你在干什么"（前台应用切换、停留时长、屏幕空闲），弹幕按**观众群**多样化播报——每个应用有自己的观众席（打开 VSCode 是程序员观众团、切到浏览器变吃瓜群众），像真的在看直播。播报走 AI 生成（更有梗），事件天然低频、共享现有文字通道闸门，不增加调用成本结构。

## 变更

### A1 AppWatcher 事件源（新文件 src/main/appWatcher.js）

- **macOS**：`lsappinfo front` 拿前台应用 bundle id（LaunchServices，**免权限**），轮询间隔 2s
- **Windows**：长驻 PowerShell 进程轮询 `GetForegroundWindow` + `GetWindowText`（user32，**免权限**；长驻避免每次 spawn 开销，保持空闲 CPU ~0%）
- 统一输出 `{ appKey, appName }`：appKey = macOS bundle id / Windows 进程名（稳定，供配置匹配）；appName = 显示名（内置常见映射表 chrome→Chrome、Code→VSCode、WeChat→微信…，叠加用户别名 `appAliases`）
- 仅**前台应用变化**时发事件；无前台窗口（锁屏等）跳过
- **v1 不做 macOS 窗口标题**（需辅助功能权限，留后续增强）；Windows 标题天然可用但 v1 不消费
- 提供 `getCurrent()`（brain 打事件上下文戳用）

### A2 事件与播报（进现有文字通道，不新增通道）

| 事件类型 | 触发 | 描述示例 |
|---|---|---|
| `app_switch` | 前台应用变化 | 用户打开了「VSCode」 |
| `app_enter` | 切换应用命中不同观众群（登场播报，见 A3） | 程序员天团进入直播间，就位！ |
| `app_stay` | 同应用停留超 `stayMinutes`（默认 20，可配，0=关） | 用户已在「VSCode」摸了 20 分钟鱼 |
| `idle` | 屏幕超 `idleMinutes`（默认 10，可配，0=关）无画面变化 | 屏幕已 10 分钟没有变化 |

- 三种事件都是 `source: 'file'` 同队列（带 `ts`，走时间窗过滤），共享缓冲/限速/批处理
- `entry.appKey` 上下文戳：文件事件入队时由 AppWatcher `getCurrent()` 打上当时的前台应用（事件场景化，见 A3）
- `app_stay` / `idle` 只播一次，离开/恢复后重新计时
- 同批同类型自动合并（狂切窗口只播一条，S1-1 兼容）
- `idle` 检测复用 ScreenWatcher 像素对比（零额外成本），**仅屏幕识别开启时**生效（visionModel.enabled）
- 本地模式/API 失败兜底：templates 池新增三类模板（app_switch/app_stay/idle 各 ≥20 条，不冷场原则）

### A3 观众群体系（应用人设 × 多样性）

**观众群 = 群名 + 3~5 个观众角色 + 场景人设 + 风格标签**。内置 5 组默认群（代码内置，不可删）：

| 观众群 | 默认绑定应用（appGroups） | 观众角色示例 |
|---|---|---|
| 程序员天团 | Code、IDEA、IntelliJ… | 秃头架构师、萌新实习生、测试老哥、产品经理 |
| 吃瓜群众 | Chrome、Edge、浏览器… | 前排瓜友、路人大妈、弹幕侦探 |
| 摸鱼大队 | 游戏/视频类 | 开黑队友、老板眼线、隔壁工位老王 |
| 学习委员 | Word、Notion、Obsidian… | 三好学生、学霸同桌、班主任 |
| 社畜同僚 | 微信、钉钉、邮件… | 摸鱼搭子、甩锅侠、热心同事 |

内置群默认绑定的完整应用映射表在实施计划中给出（按常见应用进程名/bundle id 覆盖主流场景，用户可按 appGroups 改绑）。

- **场景化 prompt**：`buildSystemPrompt` 增加场景注入参数——命中观众群时注入该群场景人设（"你是一群程序员观众，正在看一个程序员干活……"）+ 群角色 + 群风格；未命中用全局角色/风格池（现状）
- **事件场景化**：文件/应用事件带 `entry.appKey`，生成时按事件戳选群（在 VSCode 改文件，弹幕评这条时仍是程序员观众团，不受后来切窗影响）；idle/停留无应用上下文 → 全局池
- **观众群登场**：切换应用命中**不同**观众群时，额外发一条 `app_enter` 事件（描述"观众群换场"），与 `app_switch` 同批入队（两连弹效果：一条"用户打开了 VSCode"+一条"程序员天团进入直播间，就位！"）；同群切换不播。templates 池含 app_enter 兜底模板
- **自定义群**：`audienceGroups` 可新增/覆盖同名内置群（群名 + 角色 + 场景 + 风格，textarea 编辑）

### A4 配置结构（configCore monitor 扩展，旧配置自动合并兼容）

| 键 | 默认 | 说明 |
|---|---|---|
| `appWatch` | true | 前台应用监控总开关 |
| `stayMinutes` | 20 | 停留播报阈值（0=关） |
| `idleMinutes` | 10 | 空闲播报阈值（0=关） |
| `appAliases` | `{}` | 应用显示名别名 `{ appKey: 显示名 }` |
| `appGroups` | 内置绑定 | 应用→观众群映射 `{ appKey: 群名 }` |
| `audienceGroups` | `{}` | 自定义观众群（覆盖同名内置） |

### A5 设置页（monitor section 扩展 + 帮助提示模式）

**帮助提示模式（通用 UI 规范）**：复杂配置项 label 右侧 `？` 圆圈标记，hover 弹出 CSS tooltip（零依赖零构建），只解释"怎么配置"（格式/示例/默认值）。**所有新配置项强制带**，现有复杂项（噪音规则编辑、风格池编辑、隐私遮罩绘制）顺带补齐。

新配置项与提示文案：
- `appWatch`：「开启后轮询前台应用变化，弹幕会根据你正在用的应用选择观众群。轮询每 2 秒一次，几乎不占 CPU」
- `stayMinutes`：「在同一应用停留超过该分钟数时播报一次。默认 20。填 0 关闭」
- `idleMinutes`：「屏幕画面超过该分钟数无变化时播报一次。默认 10。填 0 关闭」
- `appGroups`：「每行一个：`应用: 观众群`，如 `Code: 程序员天团`。应用用英文名或你配置的别名；未列出的应用用全局观众池」
- `audienceGroups`：「每行一个群：`群名: 角色1｜角色2｜场景描述`。场景描述会注入 AI 提示词；自定义群可覆盖同名内置群」
- `appAliases`：「每行一个：`应用: 显示名`，如 `chrome: 浏览器`。用于弹幕文案显示」

设置页实现：vanilla + section 拆分（monitor section 拆出子模块），零构建不变。

## 不做

- macOS 窗口标题级监控（需辅助功能权限，A1 已注明，留后续）
- 观众昵称/头像外壳（多角色已有，外壳是纯渲染增强，另议）
- idle 恢复播报（"回来了"），保持简单
- 输入级 hook（键盘/鼠标，沿用设计文档非目标）
- 应用使用时长统计报表（本子项目只做弹幕播报）
