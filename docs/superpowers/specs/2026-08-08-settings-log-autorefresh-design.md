# 设置页日志自动刷新 设计

日期：2026-08-08
状态：已批准（用户确认：5s 间隔 + 仅窗口可见时轮询 + 新请求高亮）

## 目标

设置页"日志（发送给 AI 的请求）"面板目前只有手动"刷新"按钮。加自动刷新：日志随 AI 请求实时滚动更新，不用手动点；新请求可视高亮。性能已实测确认无碍——RequestLogger 是内存 ring（`MAX_MEMORY=100` 条），一次 IPC ≤50 条目（~150KB JSON，`getLogs(limit=50)` 默认上限；ring 存量 100 但视图只取 50）毫秒级，5s 轮询 CPU 开销可忽略（<0.1%）。

## 变更

### S4-1 自动刷新轮询（settings.js）

- 初始化处加 `setInterval`：每 5 秒，仅 `document.visibilityState === 'visible'` 时调 `renderRequestLogs()`（窗口隐藏/最小化跳过，Electron 会节流隐藏窗口定时器，双保险）。窗口销毁即渲染进程销毁，无泄漏。
- **无变化不重建**：`renderRequestLogs` 开头计算签名 `logs.length + '|' + 最新条目 ts`，与上次相同则直接 return（避免每 5s 无谓 DOM 重建）。
- **滚动位置保持**：重建前存 `box.scrollTop`，重建后恢复（否则自动刷新时阅读旧日志的滚动位置每 5s 被重置）。
- 手动"刷新"按钮保留（点按立即刷新，逻辑与自动刷新共用）。

### S4-2 新请求高亮（settings.js + settings.css）

- 渲染时维护 `seenLogKeys`（Set，条目 key = `ts|channel|error`），**只保留当前渲染的 ≤50 条**（防无限增长）。
- 新出现的条目（key 不在上次集合中）加 `req-new` 类；**首屏渲染不高亮**（首开页面所有条目都算"新"会全闪）。
- CSS：`.req-item.req-new { animation: req-flash 2s ease-out; }` + `@keyframes req-flash`（背景白雾淡出）。

## 不做

- 不改 `MAX_MEMORY`/轮转策略/日志内容格式（只读展示层）。
- 不做设置页其他区块的自动刷新（用量统计/更新区块仍手动）。
- 不做请求日志文件读取（内存 ring 足够，磁盘文件留给"打开日志目录"）。

## 验证

- `npm test` 全绿（187 现有，设置页无单测——项目惯例 CDP/实机验证）。
- 实机：打开设置页 → 触发一次文件操作/切应用 → 5s 内日志区出现新条目且有高亮动画；滚动到旧日志后新请求到达 → 滚动位置不跳；隐藏设置页窗口 → 无 IPC 轮询（主进程侧可加日志计数或直接观察无高亮变化）。
